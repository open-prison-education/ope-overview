The Problem We're Solving

Education behind the walls is hard — and it shouldn't be.

Corrections facilities need real classroom tools, but commercial LMS products assume open internet, unmanaged devices, and trusted networks. OPE was built from the ground up for the opposite reality.

📶

Limited connectivity

Network access is intermittent, restricted, or completely air-gapped in many facilities. Students still need to study every day.

🛡️

Strict security policy

Student devices must be locked down: approved network adapters only, controlled software, monitored activity, and verifiable compliance.

💰

Limited options and tight budgets

Corrections education programs need enterprise capability without enterprise licensing if any options are available — OPE is open source and delivers both.

The Solution

One platform, two halves: server and student device.

A Docker-based stack that gives each site a complete classroom: Canvas LMS, databases, caching, DNS, and optional offline learning libraries — all configured by a guided wizard.

Server Component 2 of 4

Canvas LMS — the experience students and faculty already know

Rather than reinvent the LMS, OPE hosts the open-source Canvas LMS — the same platform used by colleges and K-12 districts worldwide.

For students

  • Course pages, modules, assignments, files
  • Discussions and quizzes
  • Grades and feedback
  • A modern, familiar interface that builds digital literacy

For faculty

  • Standard Canvas authoring tools
  • SpeedGrader, rubrics, and analytics
  • Course import/export compatible with other Canvas systems
  • No new LMS to learn — drop in existing course shells

Why it matters in corrections

  • Students leaving custody have used real-world software
  • Credits and content transfer cleanly to outside institutions
  • Open source means no per-seat licensing

Integrated extras

  • Rich Content Editor (RCE) service
  • MathMan equation rendering
  • OAuth2 tokens issued for the desktop client
Server Component 3 of 4

🎓Student Management Console (SMC)

SMC is the operator-facing web console that plugs into Canvas and institutional workflows — the place staff actually spend their day.

👥 User & enrollment management

Create student and instructor accounts, manage enrollments, and align with onsite policy without needing Canvas admin-level expertise.

🔗 Institutional integrations

Hooks into Active Directory, Canvas, and WAMAP.

🎬 Media library

Approved educational video in one place — with tools for video upload, media and conversion.

🔑 Canvas token broker

During laptop credentialing, SMC issues Canvas student access tokens to the device — no shared admin keys needed.

Laptop Tool 1 of 4

🪪 Credential — first-touch device onboarding

A Windows provisioning tool (credential.exe) that takes a freshly imaged laptop and prepares it for a specific student, end to end.

✅
Validates configurationConfirms BIOS lockdown, admin privileges, and a complete JSON config.
🛡️
Applies security baselinesSets firewall rules, group policy, Defender exclusions, and registry-based settings for downstream services.
👤
Creates the student accountVerifies against Active Directory, then builds a locked-down Windows user profile.
🔑
Authenticates with CanvasFetches a Canvas access token from SMC and stores it securely for the desktop LMS client.
Installs supporting servicesDrops the OPE Service into Windows, then re-locks the device so it ships ready for the student.
# operator's workflow, abbreviated
1) edit credential_config.json   // student username, AD DN, approved NICs
2) right-click credential.exe → Run as administrator
3) review summary & confirm   // then walk away
Laptop Tool 2 of 4

OPE Service — compliance that survives past day one

A persistent Windows service (OPEService.exe) that runs in the background and makes sure the device stays in policy long after credentialing.

🕒 Scheduled tasks

  • Network interface scans (catch unapproved NICs)
  • Periodic screenshots for supervision
  • Registry & folder permission resets
  • Routine maintenance via shared mgmt routines

⚡ Event response

  • USB device plug / unplug events
  • Network adapter changes
  • Login events
  • Triggers automatic policy re-application

📝 Auditable

All activity logs to %PROGRAMDATA%\ope\logs\ope-service.log, with adjustable verbosity for troubleshooting.

Laptop Tool 4 of 4

🎓OPE LMS — the offline-capable desktop client

A Qt6-based Windows application that gives students Canvas without needing Canvas to be reachable at that moment.

What students get

📂
Browse cached coursesModules, files, pages — fully navigable offline.
📝
Work on assignmentsDraft offline, submit when the network returns.
💬
Participate in discussionsRead and post within facility-permitted boundaries.
🎬
Rich mediaOptional QtWebEngine build supports MP4 for educational video.

How it works under the hood

🔐
OAuth2 to CanvasAuthenticates with the token issued by SMC during credentialing.
💾
SQLite + local cacheCourse content downloads to a configurable drive (e.g. D:).
🌐
Built-in HTTP serverServes cached pages locally so Canvas content renders natively.
🔄
Sync on reconnectUploads work, pulls new materials, refreshes announcements.
A day in the life

How it all flows together

A single student's journey through the OPE platform — from a fresh laptop to a graded assignment.

1️⃣
Operator credentials the laptopcredential.exe verifies BIOS lockdown, creates the student account, pulls a Canvas token from SMC, installs OPE Service, re-locks the device.
2️⃣
Student signs inOPE LMS launches, authenticates to Canvas using the stored token, and downloads enrolled courses to the local cache.
3️⃣
Student works — connected or notReads modules, drafts essays, takes quizzes from cache. OPE Service screenshots and verifies compliance in the background.
4️⃣
Network window opensmgmt sync pushes completed work and screenshots to SMC; OPE LMS uploads submissions to Canvas; new content comes down.
5️⃣
Faculty grades in CanvasSame SpeedGrader, same rubrics, same workflow as any other campus.
Why corrections IT can say yes

🔒 Security posture

Every piece was designed with compliance and security in mind.

🚫

NIC allowlisting

Only approved network adapters on approved subnets are enabled. Unknown adapters are auto-disabled on plug-in.

🧱

Firewall automation

Firewall rules are applied at credentialing and re-applied on schedule by OPE Service.

📜

Group Policy

Lockdown policies enforced and continuously verified, not just at imaging time.

👥

Account discipline

Student account lifecycle managed centrally; no shared logins, no privilege creep.

🔑

Registry & ACL resets

Permissions snap back to baseline on a recurring schedule.

🔌

USB event monitoring

Plug events trigger policy verification — not silently allowed.

📸

Periodic screenshots

Time-stamped supervision evidence in %PROGRAMDATA%\ope\screenshots.

🪵

Comprehensive logging

Every tool writes to its own log under %PROGRAMDATA%\ope\logs.

🔐

Secret hygiene

SMC admin passwords live in the Windows Credential Vault; Canvas keys in .secrets.yml, out of source control.
